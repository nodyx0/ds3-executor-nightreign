# Build roadmap

## Phase 1 — Confirm the prototype is real
- Confirm Dark Souls III is the required host game.
- Confirm the project is not a standalone demo or browser mockup.
- Confirm the project only aims for solo offline first.
- Keep the design in sheets and treat them as source of truth.

## Phase 2 — Lock the design
- Fill every row and column in character, ability and systems sheets.
- Make sure each ability has a clear input, effect, cooldown and target.
- Make sure the project describes the actual DS3 route (ModEngine2), not a separate engine.
- Confirm the build remains small: one character, a few abilities, one arena test.

## Phase 3 — Build the first playable slice
- Create the real mod folder structure for a DS3 host-game patch.
- Use the game’s installed files and ModEngine2 route.
- Add the Executor character scaffold as a real playable slot, not just art or concept files.
- Test the first encounter or arena with the new character.

## Phase 4 — Test and fix
- Launch the game through the correct route.
- Check the mod loads without crashing or failing the host game.
- Confirm the character enters the game and can use the new moves.
- Fix errors and re-test before packaging.

## Phase 5 — Prepare the Melty draft
- Only list it once the project is actually playable.
- Keep the title, tagline and description grounded in the real build.
- Draft the Melty metadata and confirm the requirements are honest.
- Use a real screenshot or gameplay clip from the tested version.

## Phase 6 — Publish only when tested
- Publish only when the build is confirmed to launch and play.
- Do not publish a source-only or untested project as a mod.
- Keep the repo honest: source files and tested files must be separated clearly.
